## Implemented

- Transcription decodes bounded 16 kHz mono chunks and reuses Whisper state, preserving original word times. Native inference/download/decoder cancellation is connected to editor teardown and console signals. Complete transcripts publish atomically; cancellation preserves an existing transcript. CLI audio diagnostics analyze fixed-size blocks rather than complete tracks.
- Decoded/enhanced audio uses writable application cache storage with a 2 GiB eviction target. Shared sidecar leases protect live assets while allowing atomic cache repair/publication. GC checks ownership and excludes foreign files. Active assets may temporarily exceed the target; old package-local caches are left untouched. Failed project saves retain the editor's dirty state for retry.
- Windows key badges use Ctrl/Alt/Shift/Win labels and canonical special-key names. Modifier-only events are excluded from badges and typing detection, including compatible handling of old recordings.
- Real Windows Graphics Capture for displays, windows and regions, with physical monitor geometry and DPI conversion for the on-screen pickers. Window metadata includes actual process, position and display; window picking uses native z-order. Empty WGC frames from occluded classic windows use a bounded window-paint fallback rather than capturing the covering application.
- Standard H.264/HEVC MP4 and ProRes MOV encoding; all video frames are saved. Independent FFmpeg decoding replaces CAMF and filename-based synthetic substitution. Invalid/missing screen media is rejected when opening a project.
- Screen and camera capture writers now honor their requested codec, and screen capture forwards the requested quality rather than forcing H.264/0.95. The normal Recorder requests HEVC screen footage and H.264 webcam footage. Independent tests exercise H.264, HEVC and ProRes through both capture paths.
- Native GPU export composites directly into pooled DX12/D3D11 shared textures, converts to NV12 on the GPU and encodes through a verified hardware Media Foundation transform. Quality controls, audio muxing, edited timelines, file-size fitting and cancellation are connected. Each native export runs in an owned worker process/job so external encoder handles cannot accumulate in the editor; cancellation also cleans FFmpeg descendants and private scratch. Automatic capability probing retains the FFmpeg/software fallback.
- Runtime probing of NVIDIA/Intel/AMD hardware encoders, with software fallback. Independent ffprobe metadata identifies `h264_nvenc` on export and `hevc_nvenc` on normal screen recording on this PC.
- Separate WASAPI system/microphone WAV stems on a shared pause-adjusted clock, webcam discovery/capture, live source/camera preview, voice-over capture, and compressed-audio decoding with 48 kHz stereo resampling.
- Audio capture and voice-over now stream timestamped float WAV/RF64 files to disk. Each stem has an 8 MiB sample budget plus a bounded packet queue; samples from before video starts are clipped and paused time is removed. Cancellation cleans pending files; queue overflow stops capture while preserving usable recorded audio. A failed final rename retains a decodable recovery file and reports its location.
- Editor peak scanning, voice enhancement, timeline mixing and export now use disk-backed PCM assets and fixed-size audio blocks. Preview prefetch keeps four blocks plus an interpolation frame in memory; device callbacks do no file I/O. Live master volume, cuts/speeds, narration/ducking, music/fades and clicks remain supported. Stale preparation cancels, errors reach the editor, and workers join on exit. Export muxes a temporary WAV/RF64 without loading the soundtrack into memory.
- Voice levelling now sums energy in double precision, fixing an audible gain difference caused solely by track length. Export rejects empty/invalid timelines before rendering, and cancellation remains active through final audio muxing.
- The previously ignored `exclude_own_audio` option now selects native Windows process-loopback capture, excluding Cam and its descendants while retaining audio from other processes. Endpoint loopback remains available when exclusion is disabled. Source selection uses explicit microphone/system variants.
- Windows global hotkeys and conflicts, floating recording controls, tray menu/status, keyboard logging, native cursor images/hotspots, graceful console cancellation, and working synthetic diagnostic recording.
- Clipboard file-drop payload, truthful clipboard/save errors, window resize readback/errors, privacy status checks, and desktop/taskbar restoration. Recorder names cannot overwrite an existing project. Cancelled/failed exports preserve an existing destination, including GIFs; recording cancellation discards encoder/audio work rather than finalizing unwanted files.
- Editor exit and application teardown cancel/join an active export instead of detaching it. Export staging uses exclusive creation before claiming cleanup ownership, preserving any foreign or old staging file.
- RNNoise neural voice isolation, existing levelling/DSP, and full-duration two-pass file-size fitting for H.264 and HEVC.
- Live preview texture upload and egui texture-delta lifecycle fixes. Hotkeys are shut down before Windows tears down worker threads, avoiding an exit-time panic. Existing saved Apple key codes migrate to Windows key codes, with a format marker preventing repeat conversion.
- Preview devices are released before recording starts, including an in-progress asynchronous camera startup. This prevents exclusive webcam ownership conflicts with countdown disabled. Preview workers also stop on application exit.
- Windows build/selftest scripts and independent media regression tests.

## Runtime requirements and remaining differences

- FFmpeg and ffprobe must be on PATH, next to cam.exe, or configured through CAM_FFMPEG/CAM_FFPROBE. They are installed on this PC. Licensing notes are in THIRD_PARTY_NOTICES.md.
- Native H.264/HEVC export is selected automatically when its adapter, encoder and format checks pass. `CAM_NATIVE_ENCODER=require` requires it; `off` selects the established FFmpeg route. `CAM_ENCODER=software` disables native selection. ProRes/GIF retain their existing routes. GPU source decoding and direct GPU capture remain separate, incomplete parity capabilities; the native export bridge removes compositor readback, not all CPU media transfers.
- Direct macOS-style USB iPhone/iPad screen capture remains unavailable. The device source accepts video exposed through a Windows DirectShow driver; pairing/trusting a USB iPhone alone does not supply that stream. No iPhone/iPad was available for validation.
- Hardware encoding availability depends on the GPU/driver and requested dimensions. Very small test images and ProRes use software encoding. Other GPU vendors were not available for live verification; 100%/125% mixed-DPI displays were verified.
- Existing CAMF placeholder files never contained complete recordings and cannot be recovered into real motion video. They are rejected instead of being silently replaced with demo footage.
- Process-excluding capture requires Windows build 20348 or later, as specified by [Microsoft's application-loopback API](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/); unsupported systems report a capture error rather than silently including Cam's audio.
- WASAPI reported transient buffer underrun/overrun events during device startup on this PC. Streams continued and the independent recorded/exported tone checks passed. Fatal stream errors now propagate to stop recording; automatic device reconnection is not implemented.
- Production capture, editor peak scanning, playback, export, transcription and CLI audio diagnostics use bounded audio sample buffers; hour-long acceptance passed. Decoded caches use approximately 384 kB per second per stereo source, and enhancement creates additional disk-backed assets. Sufficient cache/temp disk space is required. Application audio cache targets 2 GiB of inactive owned PCM assets, with active leases allowed to exceed that target. Compatibility/reference full-buffer helpers and the hidden `denoise` diagnostic are not long-input production paths. Whisper base was verified; small/medium model weights were not downloaded for this review.
