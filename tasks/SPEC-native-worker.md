# Native export process lifetime

Repeated in-process exports on the connected NVIDIA/Windows Media Foundation stack retain about 38 process handles and 20 KiB of reported local GPU usage per job despite sink release, allocator uninitialization, explicit transform shutdown, device/context cleanup and thread exit. A bounded single export does not establish bounded repeated use.

Production native export therefore runs one job in a dedicated copy of the current application. A versioned JSON request carries the current unsaved project, recording, source and settings. An eight-byte progress file and cancellation marker connect parent and worker. The child starts media work only after the parent assigns it to a Windows kill-on-close job object. Native surfaces, hardware transforms, audio scratch and mux subprocesses belong to this lifetime.

The worker writes only inside an exclusively created staging directory beside the intended output. Source packages and imported media are borrowed. Native audio uses a cache inside that directory, so forced termination cannot leave partial native soundtrack/cache assets in the source package. The parent waits/reaps the worker and terminates remaining descendants before publishing the completed output. Cancellation is cooperative initially, followed by job termination after three seconds. Crash, invalid result, cancelled jobs and initialization errors preserve the destination. Automatic capability fallback remains supported; it never reruns a failed in-flight render silently.

Acceptance: repeated native H.264/HEVC exports must independently decode and leave stable parent handles/GPU usage; verify old-destination preservation and staging cleanup for cancellation/crash, progress delivery, audio/edit/quality/size-target behavior and fallback. Hardware tests use the application binary built in their own Cargo profile. The native encoder itself still performs normal orderly shutdown; process isolation is additional cleanup for external resource lifetime. Source GPU decoding and capture remain separate capabilities.

The editor export owner now cancels and joins its worker on replacement/drop, and the application exit hook does the same before Windows teardown. The outer export staging guard also uses exclusive file creation before taking cleanup ownership. A focused lifetime regression verifies the export thread cannot escape its owner.
